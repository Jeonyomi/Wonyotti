# 공개 거래내역 검증 노트

워뇨띠 공개 거래내역의 과거 거래·성과를 확인하고, 사람이 기록을 읽으며 참고할 관찰을 정리하는 독립 비공식 프로젝트입니다. 워뇨띠·BitMEX의 공식 서비스가 아니며 제휴·승인·보증을 받았다는 뜻이 아닙니다. 투자 조언, 매매 추천, 미래 성과 보장을 제공하지 않습니다.

**v1.1.0 · 수동 현황 스냅샷 2026-09-22.** 이 날짜는 실시간 조회 시각이나 원문 게시일이 아닙니다. 원본 거래·지갑 파일은 미확보, 원본 구조는 미확인, 실제 검증은 미실행입니다.

[정보·출처·개인정보 원칙](docs/INFORMATION-POLICY.md) · [개발·공개 체크리스트](docs/PUBLISHING.md) · [오류 제보](https://github.com/Jeonyomi/Wonyotti/issues)

## 공개 목적과 이용 경계

다음은 **사용자가 전달한 공개자 공지의 요약**입니다. 원문 URL과 게시 시각이 없어 독립적으로 진위를 확인하지 못했으며, 당사자의 인증된 직접 인용이나 법률적 판단이 아닙니다.

- 공개 취지는 과거 거래·성과를 확인하고 사람이 기록에서 참고할 점을 얻도록 하는 것입니다.
- 공개 자료를 알고리즘 학습용으로 제공한 것이 아니며, 허락 없는 봇 제작·배포·판매를 하지 말라는 취지입니다.
- 체결 내역만으로 거래하지 않은 판단, 취소한 주문, 매매 이유까지 복원할 수 없습니다.
- 닉네임을 내세운 봇을 구매하거나 신뢰하지 말라는 경고가 포함돼 있습니다.

이 프로젝트는 **자동매매 알고리즘 학습·무단 봇 제작·배포·판매에 사용하지 않습니다.** 공개 접근 가능성과 재배포·상업적 이용·외부 서비스 업로드 권한은 별개입니다. 자료별 허락 범위가 불명확하면 해당 이용을 보류합니다.

## 현재 제공하는 것

| 항목 | 상태 |
|---|---|
| 거래·지갑 원본 | `dataset_status: NOT_ACQUIRED` |
| 실제 열·단위·식별자 | `schema_status: UNVERIFIED` |
| 공개 체결 대조·회계 검증 | `verification_status: NOT_RUN` |
| 원문 게시 URL·게시 시각·파일 해시 | `null` — 미확인 |
| 사이트 | 정적 안내와 브라우저 안의 출처 탐색·공유 요약·인쇄 |

사이트에는 자료 수집·업로드·계정 연결·거래 실행 기능이 없습니다. 아래 내용은 과거 자료를 검토할 때의 확인 기준이며, 이미 실행된 분석이나 구현된 처리 기능이 아닙니다. 실제 데이터 감사·장부 대사·성과 보고서는 없습니다. 미확인 값을 예시 수익 곡선이나 진행률로 채우지 않습니다.

## 1. 출처와 파일 목록부터 확인

원문 게시물, 작성자가 연결한 배포 위치, 거래·지갑 파일과 설명서를 구분합니다. 재전파 글이나 미러는 원본 인증 자료로 취급하지 않으며, 다운로드 주소를 추측해 만들지 않습니다.

- 게시 URL·게시 시각·자료 제공자·허락 범위·실제 조회 시각을 각각 기록합니다. 모르는 값은 미확인으로 남깁니다.
- 파일별 출처 URL, 최종 다운로드 URL, 정확한 바이트 수, SHA-256, 실제 파일 형식, 압축 항목을 기록합니다.
- 숨김 시트를 포함한 전체 시트·행·열·헤더·요약 행과 읽을 수 없는 부분을 조사합니다. 공지의 대략적인 규모에 맞춰 기록을 자르지 않습니다.
- 해시는 받은 파일의 동일성과 변경 여부를 확인하는 수단입니다. 공개자의 신원이나 내용의 진위를 증명하지 않습니다.
- 원본은 저장소 밖의 접근 제한 공간에 보관하고 검토용 사본과 분리합니다. 매크로·외부 링크·수식을 실행하지 않습니다.
- 원문 위치와 변환 근거를 남깁니다. 오류·중복·제외 행은 이유 없이 삭제하지 않고 각각 집계합니다.

긴 식별자는 문자열로 보존합니다. 숫자로 읽으며 잃은 자릿수는 나중에 문자열로 바꿔도 복구되지 않습니다. 원본 시각·시간대 근거·정밀도를 함께 남기며, 관측하지 않은 정밀도를 만들어내지 않습니다.

## 2. 공개 체결과 비교할 때

공개 체결 ID와 계정 체결 ID가 같은 뜻인지 먼저 확인합니다. 모양이 비슷한 식별자를 변형해 공통 키로 만들지 않습니다. 공통 키가 확인된 경우에도 종목·시각·가격·수량·방향의 의미와 집계 단위를 함께 확인합니다.

| 결과 | 기록할 내용 |
|---|---|
| 일치 | 사용한 키·필드·시간 정밀도·허용오차와 근거 |
| 후보 일치 | 공통 키 부재, 복수 후보 등 확정할 수 없는 이유 |
| 충돌·불일치 | 충돌한 필드와 확인한 자료 범위 |
| 대조 불가 | 날짜·상품별 자료 공백, 접근 실패 또는 단위 미확인 |

전체 행과 대조 가능한 행의 분모를 함께 제시하고 날짜·상품별 공백을 숨기지 않습니다. 공개 자료가 없다는 것과 불일치는 다른 결과입니다. 공개 체결의 방향과 개인 계정의 매수·매도 방향이 같은 의미라고 가정하지 않습니다.

**공개 체결 일치는 계정 소유나 공개 내역의 완전성을 인증하지 않습니다.** 공개본 내부의 누락 여부, 다른 계정의 존재, 전체 기간 공개 여부는 별도 증거가 필요합니다. 제거된 주소나 신원을 역추적하지 않습니다.

## 3. 금액·손익·잔액을 대사하는 기준

종목 이름만으로 계산식을 정하지 않습니다. 당시 계약 유형, 승수, 수량 단위, 결제 통화, 수수료·펀딩·정산 규칙을 확인합니다. 현재 계약 명세가 과거에도 같았다고 가정하지 않습니다.

- 금액은 통화별 최소 단위 또는 정확한 십진수로 다루고, 통화가 다른 값을 그대로 합산하지 않습니다.
- 수수료율과 수수료 금액을 구분합니다. 수수료·리베이트·펀딩의 수취와 지급 부호를 확인합니다.
- 원본 보고 손익, 체결과 계약 명세로 재계산한 손익, 지갑에서 인식된 현금 흐름은 별도로 비교합니다.
- 누적 손익 열을 개별 거래 손익처럼 합산하지 않습니다. 거래 이력과 지갑 이력에 함께 있는 손익·펀딩·수수료를 두 번 더하지 않습니다.
- 출금액이 이미 수수료를 포함한 순액인지 확인합니다. 정산 손익도 다른 항목에 중복 반영하지 않습니다.

통화별로 기초 잔액에 입금을 더하고 출금을 빼며, 서로 중복되지 않는 매매 손익·펀딩·수수료·확인된 기타 현금 흐름을 반영해 기말 잔액과 비교합니다. 감사 범위 안의 계정 간 이전과 범위 밖 입출금을 구분합니다.

차이는 미설명 차액으로 남깁니다. 잔액을 맞추기 위해 근거 없는 조정액을 넣지 않습니다. 반올림·허용오차는 최소 통화 단위와 당시 규칙에 근거해야 합니다. 잔액이나 계약 명세가 없으면 그만큼 검증 범위를 낮춥니다.

## 4. 사람이 읽을 수 있는 포지션 관찰

시작 포지션과 순서가 확인된 범위에서 보유 수량의 증가·감소, 부분 정리, 잔량이 없어지는 시점, 방향 전환을 기술할 수 있습니다. 체결 수·주문 수·포지션 구간 수는 서로 다르며, 주문 ID가 없으면 실제 주문 수를 확정하지 않습니다.

시작 수량을 모르면 처음부터 잔량이 없었다고 가정하지 않습니다. 마지막 미청산 포지션도 임의로 종료하지 않습니다. 같은 시각의 순서나 계정 구분이 불명확하면 가능한 해석과 한계를 함께 씁니다.

관찰에는 기간·상품별 손익 분포, 보유 시간, 수량 변화, 손익 집중 구간과 손실 구간을 함께 담을 수 있습니다. 실제 자료가 없는 현재는 이러한 관찰 결과도 없습니다.

**관측한 수량 변화와 숨은 의도는 다릅니다.** 체결 시각은 판단 시각이 아닐 수 있습니다. 거래하지 않은 이유, 취소·미체결 주문, 외부 계정 거래, 당시 화면, 선택한 레버리지와 판단 근거는 기록 없이 복원할 수 없습니다. 사람이 참고할 설명을 매매 규칙이나 미래 수익 약속으로 바꾸지 않습니다.

## 5. 과거 성과·위험의 정의

| 항목 | 확인할 조건과 한계 |
|---|---|
| 총입금 대비 순실현손익 비율 | 기간·수수료·펀딩 포함 범위와 분모를 명시하며 연수익률로 부르지 않음 |
| 계정 순자산 | 해당 범위의 잔액과 미실현손익을 함께 확인 |
| 시간가중수익률(TWR) | 외부 입출금과 그 전후 평가액이 있어야 하며 근사치는 따로 표시 |
| 금액가중수익률(MWR/XIRR) | 현금 흐름 시점이 필요하며 해가 없거나 여러 개일 가능성을 설명 |
| 최대 낙폭 | 외부 입출금 효과를 구분한 순자산 시계열과 관측 간격을 명시 |
| 노출·담보 위험 | 명목 노출과 순자산, 담보 통화 변화를 구분하며 실제 선택 레버리지는 추정하지 않음 |
| BTC·USD 성과 | 각 시점 환산 기준과 담보 가격 효과를 구분 |

자료가 일별이라면 일중 최대 손실을 확인했다고 하지 않습니다. 과거 BTC 손익에 현재 가격을 곱한 금액을 당시 수익률로 표시하지 않습니다. 공지의 수치나 산술 일치는 원본·기간·정의가 확인된 성과와 별개입니다.

## 6. 참고 자료와 확인 범위

다음 링크는 일반 문서와 공개 자료의 탐색 시작점입니다. 원문 공지·개인 거래 파일의 출처가 아니며, 이번 개정에서 링크의 최신성이나 과거 파일 다운로드 성공을 새로 확인했다는 뜻도 아닙니다.

| [Microsoft · Excel 사양과 한도](https://support.microsoft.com/en-us/excel/excel-specifications-and-limits) | 시트 구성·식별자 정밀도 확인 참고 |

## 로컬 화면 확인

Node.js 24 이상을 사용합니다. 브라우저 실행 코드는 HTML·CSS·JavaScript이며, jsdom·Playwright·axe는 개발·검사용 의존성입니다.

```bash
npm ci
npx playwright install chromium
npm test
npm run check
npm run build
npm run test:browser
npm run preview
```

명령은 실행 안내이며 통과·배포 기록이 아닙니다. 빌드 결과는 `dist/`입니다. 브라우저 검사는 먼저 빌드한 뒤 실행하고 미리보기 주소는 터미널 출력으로 확인합니다. 테스트 통과는 거래 진위나 성과의 검증이 아닙니다.

## 개인정보·공개·정정

앱에는 분석 추적·광고·로그인·업로드·방문자 정보 저장 기능이 없습니다. 화면 조작은 브라우저 안에서 처리하지만, 정적 자산 요청과 호스팅 제공자의 접속 로그까지 없다는 뜻은 아닙니다. 외부 링크에는 해당 서비스의 정책이 적용됩니다.

공개·배포·검색 색인은 별도 검토 대상이며 승인 전 `noindex`를 유지합니다. 이는 접근 제어나 비밀 보호 수단이 아닙니다. 원본 거래·지갑 파일, 주소, 계정 식별자, API 키·개인키를 Git이나 공개 이슈에 올리지 않습니다.

정정 요청에는 문제가 있는 문구와 공개 근거 또는 재현 절차만 남겨 주세요. 확인된 범위·수정 내용·수정일을 기록하며, 제보 자체를 당사자 인증이나 자료 이용 허락으로 간주하지 않습니다.
